# Kotoba Studio · UI 设计说明（可直接作为 prompt 使用）

> 这份文档既是给设计师/设计 AI 的需求说明，也是仓库里界面实现的依据。
> 下面出现的所有日语、中文文案、数字都是产品里真实存在的内容，请直接使用，不要用占位文本。

---

## 1. 这是什么

**Kotoba Studio 是一个"会记住语境的日语伴读工具"。**

用户在玩日文 Galgame 或看日语动画时，遇到看不懂的台词，用它把**整句台词 + 当时的截图**收下来；
玩完之后再回来，点出句子里不认识的词，确认成词卡；之后用 FSRS 间隔重复算法在电脑或手机上复习。

它不是词典，也不是翻译器，更不是 Anki 的前端——它自己就是完整的学习应用，导出到 Anki 只是可选出口。

一句话概括产品主张：**别人做的是"截图取词器"，我们做的是"把偶遇变成长期记忆的闭环"。**

## 2. 用户是谁，在什么场景下用

目标用户：**中文母语的日语学习者**，大致 N4–N2 水平，正在玩生肉 Galgame 或看无字幕/日文字幕动画。
典型痛点是：认得汉字但读不出音；查得到词典义但不懂这句为什么这么说；被中日同形词误导。

界面必须同时服务四个差异很大的使用场景，**这是整个设计最重要的约束**：

| 场景 | 设备与姿态 | 注意力 | 对设计的要求 |
| --- | --- | --- | --- |
| **采集** | 电脑，游戏在全屏或另一屏，本应用在副屏/后台 | 几乎全在游戏上，只想瞥一眼 | 主操作必须极其显眼、一眼可命中；文字越少越好；快捷键优先 |
| **整理（收件箱）** | 电脑，游戏已结束，专心坐在屏幕前 | 完全在应用上 | 信息密度可以高；需要同时看到句子、分词、词典候选、截图 |
| **短测** | 电脑或手机，刚整理完，3 分钟 | 集中但短暂 | 一次只呈现一道题；反馈要清楚（对/错/正确答案） |
| **复习** | 手机，通勤或睡前，单手 | 碎片化 | 字要大；评分按钮在拇指可及范围；正面信息极简 |

## 3. 硬约束（实现层面已经确定，设计必须遵守）

1. **中日双语同屏。** 界面文案是简体中文，学习内容是日语。两种文字会紧挨着出现（例如
   "词条 奢る（おごる）请客"）。日语需要单独的字体栈与字号处理，不能和中文用同一套。
   日语汉字与中文汉字字形不同（如 直/直、骨/骨），必须用日文字体渲染日语。
2. **同一套代码跑桌面和手机。** 桌面是左侧 200px 固定导航；手机是顶栏 + 底部 5 个 Tab
   （首页/收件箱/复习/词库/设置，"采集"在手机上隐藏，因为采集必须在电脑上进行）。
   断点在 768px。
3. **明暗两套主题**，跟随系统，也可手动切换。
4. **复习卡正面绝不能泄题。** 正面不出现截图、不出现包含答案的完整句子。这是产品规则，
   不是可选项。填空卡正面是挖空后的句子（今日は俺が＿＿てやるよ。），读音卡正面只有词。
5. **PWA。** 手机通过扫码打开后"添加到主屏幕"，需要考虑没有浏览器地址栏、有安全区
   （刘海/底部横条）的情况。
6. **离线可读。** 弱网时已缓存的界面要能打开，不能白屏。

## 4. 需要设计的界面（按优先级）

### P0 —— 这三个决定产品成败

#### 4.1 复习（`/review`）· 手机优先
产品的核心循环。每张卡两个状态：**正面（提问）** 与 **背面（揭晓）**。

- 顶部：`复习` + 右侧 `本设备（手机）· 剩余 12 · 已复习 8`
- **正面**（三种卡型，设计需覆盖）：
  - 读音卡：巨大的 `奢る`，下方小字提示 `怎么读？在这句里是什么意思？`
  - 填空卡：`しょうがないなぁ…今日は俺が＿＿てやるよ。` + 提示 `空缺处是什么？`
  - 释义卡：`奢る（おごる）` + 提示 `什么意思？`
- 正面底部一个通栏按钮：`显示答案（空格）`
- **背面**依次出现：词 `奢る` / 读音 `おごる` / 中文释义 `请客、请（某人）吃饭` /
  可选的**中日同形警告块**（见下）/ 原句（目标词高亮）`今日は俺が**奢っ**てやるよ。` /
  截图缩略图 / 可选的 AI 语境解释 / 遇见次数 `另在 2 处遇见过`
- 背面底部四个评分按钮，每个带下次间隔：
  `忘了 <1分钟` `困难 5分钟` `记得 9分钟` `简单 9天`
  （颜色需要区分，但不要用刺眼的红绿；键盘 1/2/3/4）

**中日同形警告块**（产品差异点之一，需要专门设计，不能只是一行小字）：
> 勉強（べんきょう）
> 中文「勉强」＝ 勉强、将就
> 日语「勉強」＝ **学习**；(商家)让价

#### 4.2 收件箱 / 整理（`/inbox`）· 桌面优先
把"收下来的句子"变成"卡片"的地方，是信息密度最高的界面。

桌面左右两栏（左 2 : 右 3）：

- **左栏**：会话筛选下拉（`Summer Pockets · 10 小时前 · 1 句`）、状态筛选
  （待整理/已确认/已丢弃）、句子列表。每条含截图缩略图、日语原句、
  `10 小时前 · 1 个词`。
- **右栏上部**：大截图 + **分词后的可点击句子**。这是最关键的组件：
  句子被切成词块，每块按状态着色——
  - 未学（要点的）：强调色
  - 学习中：另一种色
  - 已掌握：弱化
  - 助词、标点等非内容词：灰色、不可点
  - **多词组成的固定表达**（しょうがない = しょう+が+ない）需要视觉上合并成一块，与单词区分
  下方一行缩约提示 chip：`しょうがない ← しようがない`、`って ← と（いう）`
- **右栏下部（点词后出现）**：词条编辑器——词典候选列表（每条：`奢る おごる [常用]` +
  英文释义）、词条/读音输入框、`中文释义（这里的意思）` 输入框、
  卡片类型勾选（读音/释义/填空）、`确认并建卡` + `取消`。
- 确认后出现结果块：`已记录 奢る，第 1 次遇见` + `AI 解释这句（可选）` 按钮。

手机上这两栏必须变成可用的单栏流程（列表 → 点句子 → 整理 → 返回列表），请给出手机版方案。

#### 4.3 采集（`/capture`）· 仅桌面
用户玩游戏时瞥一眼的界面，**当前实现是这几个界面里最弱的一个，最需要重新设计**。

包含：会话状态条（`会话进行中 · Summer Pockets` + `结束会话并整理`）、显示器选择、
`截取屏幕预览`、在预览图上**拖拽框选对话框区域**（框选后显示
`区域：172, 179 · 1054×395（已随作品保存）`）、OCR 引擎选择、
两个动作 `只识别，不保存` 与 **`收藏这句（⌘/Ctrl+Enter）`**、识别结果预览、
手动粘贴框（给 Textractor 等 Hook 工具用）、右侧"本次收藏"实时列表。

设计难点，请重点解决：
- `收藏这句` 是唯一的高频操作，必须在视觉上压倒其他所有元素，让人余光就能找到。
- 其余选项（显示器、引擎、手动粘贴）是一次性设置，不应该和主操作抢注意力，但也不能藏到找不到。
- 框选区域这一步只在每个作品第一次做，之后复用——已设置和未设置两种状态要一眼可分。

### P1

- **首页（`/`）**：当前是三个数字卡片（待复习/待整理/卡片总数）+ 进行中的会话 + 作品列表 +
  最近会话。**三个大数字很平庸，欢迎重新构想**——真正重要的是"现在该做什么"：
  有待复习就去复习，有待整理就去整理，都没有就去玩游戏。
- **词条详情（`/terms/:id`）**：词头 + 释义 + 同形警告 + **语境时间线**（这个词在哪些作品、
  哪句话、什么时候遇到过，带截图）+ 卡片列表（含归属设备切换）。
  时间线是产品的情感价值所在——"你和这个词的相遇史"，值得好好设计。
- **短测（`/quiz/:sessionId`）**：单题呈现，输入框，提交后显示对/错与正确答案
  （错时用差异高亮指出错在哪）。最后一屏是**会话复盘**：收藏 1 · 确认 1 · 新词 1 · 再见词 0，
  建卡 2 张 · 短测 2/3 · 时长 7 分 48 秒。
- **词库（`/library`）**：搜索 + 状态筛选 + 词条列表。列表项需要容纳：日语词 + 读音 +
  中文释义 + `1 次 · 1 部` + 状态标签 + 可能的 `同形` `再见词` 标记。

### P2

- **作品（`/sources`）**：添加表单 + 作品卡片列表。
- **设置（`/settings`）**：八个分区（连接手机二维码、本设备、复习、AI、词典、OCR 引擎、
  导出 Anki、备份）。当前是八个等价的卡片堆叠，缺少层次。

## 5. 现在的视觉基调与我想要的改变

当前配色（可以推翻，但请说明理由）：

| 角色 | 值 | 说明 |
| --- | --- | --- |
| 背景 | `#faf7f1` | 暖米白，想要"纸"的感觉，长时间阅读不刺眼 |
| 次级面 | `#f2ecdf` | |
| 主文字 | `#2b2a28` | |
| 强调色 | `#d9773b` → `#b5541c` | 陶土橙 |
| 语义色 | 抹茶绿 `#6b8f4e`、梅紫 `#8c5a7a`、天蓝 `#4f7fa8` | 分别用于"已掌握"、"表达"、"学习中" |

想要的气质：**温暖、安静、像一本用旧了的笔记本**，而不是科技感或游戏感。用户是在玩
Galgame 的间隙用它，界面不该和游戏抢视觉。参考感觉：纸质单词本、和纸、旧书页——但**不要**
做成拟物或过度装饰。

我自己觉得当前实现的问题（欢迎不同意）：

1. 所有区块都是同一个圆角 + 同一个阴影的卡片，层次被抹平了，看不出哪个重要。
2. 分词词块用四种颜色编码状态，颜色一多就读不出信息，需要更好的编码方式。
3. 复习卡背面信息很多（读音、释义、警告、原句、截图、AI 解释），现在是简单堆叠，缺少节奏。
4. 首页的三个大数字很像模板。
5. 日语和中文的字体/字号层次不够清晰，两种文字混排时容易糊在一起。

## 6. 希望交付的内容

优先级从高到低：

1. **复习卡**：正面 × 3 种卡型、背面（含同形警告与 AI 解释块）、评分按钮组。手机 + 桌面。
2. **收件箱**：桌面双栏完整状态（选中句子 + 分词 + 词条编辑器展开）、手机单栏流程。
3. **采集**：已框选与未框选两种状态，重点是主操作的视觉权重。
4. 首页、词条详情（时间线）、短测（答题 + 复盘）、词库列表。
5. **设计语言说明**：色板（含暗色）、字体（中/日分别）、字号阶梯、圆角与阴影的使用规则、
   按钮与标签的层级、间距节奏。

每个界面请给出**明亮**与**暗色**两版，手机稿按 390×844 设计。

## 7. 请不要

- 不要用占位文本。本文档里的日语句子、中文释义、数字都是真实内容，请直接用。
- 不要把日语当成装饰性的"异国文字"排版——它是学习内容，必须清晰、可读、字号足够。
- 不要在复习卡正面放任何会泄露答案的东西。
- 不要用紫蓝渐变 hero、不要 emoji 当分区图标、不要所有东西都居中、不要给每个卡片加彩色左边框。
- 不要为了美观牺牲信息密度：收件箱本来就需要一次看到很多东西。
- 不要设计登录/注册/账号/付费界面——本产品没有账号，数据完全在本地。

## 8. 参考：真实内容清单（直接取用）

- 作品：`Summer Pockets`（日文原名 `サマーポケッツ`）、`CLANNAD`、`白色相簿2`
- 台词：`しょうがないなぁ…今日は俺が奢ってやるよ。` / `え、本当に？じゃあ遠慮なく！` /
  `明日も晴れるといいね。`
- 词条：`奢る（おごる）` 请客、请（某人）吃饭 ／ `遠慮（えんりょ）` 客气、顾虑 ／
  `しょうがない` 没办法、拿你没辙
- 同形词：`勉強` 中文=勉强／日语=学习 ； `大丈夫` 中文=男子汉／日语=没关系 ；
  `手紙` 中文=卫生纸／日语=信
- 缩约：`ちゃう ← てしまう` ／ `なきゃ ← なければ` ／ `しょうがない ← しようがない`
- 状态词：未学 / 学习中 / 已掌握 / 忽略
- 卡片类型：读音 / 释义 / 填空 / 听音
- 评分：忘了 / 困难 / 记得 / 简单
